# Alife 运维套件

面向 Alife 5.x 的运行时体检与开发辅助插件。定位是**体检与取证** —— 发现问题、给出修法，但不自动改代码。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| **编译错误取证** | 插件编译失败时模块会直接从功能列表消失，唯一证据是宿主写进 `alife.log` 的 Roslyn 诊断。按插件聚合，并自动识别「已修复」（dll 比报错时间新就不报） |
| **一键体检** | 聚合页面审计、插件冲突、依赖问题、失效模块引用、资源告警、自检失败，每条带「怎么修」并可跳到对应页面 |
| **进程归因** | 把进程与显存按插件归因，看谁在涨 |
| **配置保险库** | 配置快照、逐行 diff、单文件回滚；回滚前自动存 `pre-rollback` |
| **热重载 diff** | 重载前后对比，确认改动是否真的生效 |
| **残留扫描** | 失效端口文件、孤儿数据目录、角色配置里引用了不存在的模块 |
| **插件档案** | 75 个插件一张表：版本、大小、改动时间、启用角色、依赖、欠测提醒 |
| **页面审计** | 检查页面遮挡层与重复 DOM id |
| **插件脚手架** | 生成 `manifest.json` + 模块 + 配置 + 入口 UI + 占位页，生成结果实测可编译 |

## 面板

模块详情页点「打开运维面板」，顶部标签：

```
概览 · 插件与冲突 · 插件档案 · 配置保险库 · 页面审计 · 重载 diff · 残留 · 编译 · 告警
```

**编译页**分两栏：未修复（按插件分组，列出 `文件:行 CS编号 消息`）、已修复（证明修过，而不是没扫到）。

## AI 工具

| 工具 | 作用 |
| --- | --- |
| `opscheck` | 一键体检，返回带修法的问题清单 |
| `opscompile` | 查编译失败，从宿主日志捞真实诊断 |
| `opsconfigs` / `opsconfigdiff` / `opsrollback` | 配置留档、差异、回滚 |
| `opspanel` | 获取面板地址 |

## 编译错误的判断依据

编译失败不产出 dll。所以：

```
插件 dll 存在 且 dll 时间 > 报错时间 + 2 秒  →  已修复
```

时间不明或没有 dll 时保守地当作仍未修复 —— 宁可多报一条，也不能吞掉真错误。日志只读尾部 4000 行，避免几十万行日志拖慢体检。

## 边界

+ 无法精确映射「哪个插件产生了哪个 WebView2 子进程」
+ 页面审计只读信息，不修改
+ 配置保险库只管理 `Configuration/*.json`
+ 定位是体检取证，不自动修复
